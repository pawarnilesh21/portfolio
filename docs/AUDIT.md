# Portfolio V2 audit

Date: 2026-10-25. Scope: existing portfolio, supplied resumes/inventory, public repositories and local project evidence. Other project repositories were read only. No messages, subscriptions, signups, refunds or form submissions were made.

## Executive finding

The old portfolio undersells substantially stronger work. Upgrade the existing Next.js App Router structure, replace presentation/content, and modernize dependencies. Do not rewrite project history to match an ideal job description. The most important publication risk is disagreement between resumes, local code and currently deployed/public versions.

## Existing application

- Next.js 14.2.16, React 18, TypeScript, Tailwind 3, local Inter TTF fonts, Lucide and a large mostly unused Radix/shadcn component collection.
- Six routes: /, /about, /skills, /projects, /achievements, /contact. Root layout supplies navbar/footer; page wrappers repeat main elements and padding.
- Static export enabled; images unoptimized. No portfolio backend included. Contact posts to http://localhost:3200/contact, which cannot serve normal remote visitors.
- A Bun lockfile exists, but its root name is my-v0-project while package.json says portfolio. No engines field, README, CI, test suite, ESLint configuration or Prettier configuration found. npm's global shim is broken on this host; the installed npm-cli.js works.
- TypeScript strict is already true. The actual build disables type validation and linting, so a successful build alone is not a quality gate.
- Content is embedded in client components. Nearly every content section waits for useEffect to reveal itself; static server output is initially hidden. Animations lack reduced-motion overrides.
- Home has no internship or featured-project proof. Project and certificate images are placeholders. Duplicate project ID 1 creates duplicate React keys. Certification CTA is a noninteractive div.
- Theme state loads from localStorage without applying the dark class. Existing next-themes provider is unused. About image references .PNG while disk file is .png; case-sensitive hosting can fail.
- Contact lacks persistent labels/status semantics and dark-theme styling. Nested main landmarks, heading-order issues, low-contrast footer text, no skip link, and incomplete mobile-menu disclosure semantics need correction.
- Route metadata exists, but root metadata remains My App/Generated by Next.js/v0.dev. No verified canonical URL, sitemap, robots, social images or Person JSON-LD found.
- Old biography/education/social links conflict with supplied resumes. Use corrected sources in CONTENT_TODO.md.

## Baseline verification

- Production build: passed with existing lint/type bypasses. Separate tsc --noEmit --incremental false: passed.
- Export: nine static pages including framework error routes. First-load JS: home 96.5 kB; contact 109 kB. Contact's Axios dependency is unnecessary for an email-first replacement.
- Mobile Lighthouse 13.5.0 against the freshly built export at http://127.0.0.1:3100/: **Performance 75, Accessibility 94, Best Practices 96, SEO 100**. LCP **8.1 s**, CLS **0**, TBT **10 ms**.
- One local lab run, simulated mobile throttling (4x CPU, 150 ms RTT, ~1.6 Mbps), Edge/Chromium 156. Scores are not production field data. No real-user INP measured; TBT is not INP. Python static serving lacks production compression/cache policy, so deployed performance must be remeasured.
- Lighthouse failures include contrast, heading order, console errors, cache policy, render blocking and large font/network dependencies. Raw report: evidence/lighthouse-baseline.json (local artifact, ignored by Git).
- Browser audit checked the five supplied live URLs and homepage at 360 px; screenshots saved locally. Separate route audit checks all six routes at 360/768/1280/1920 px (evidence/route-audit.json).
- In-app browser initialization failed with “failed to write kernel assets”; bundled Playwright and installed Edge supplied the read-only browser checks instead.
- All 24 route/viewport checks returned HTTP 200. At 768px every route overflowed horizontally. Contact had three unlabeled fields and no h1 at every width; every route had two main landmarks. Stored dark mode did not restore. The photo loaded on Windows, which does not remove its case-sensitive deployment risk.

## Dependency/security audit

The lockfile's 281 unique package names were queried against npm's bulk advisory endpoint. Seventeen package names returned advisories: @babel/runtime, axios, brace-expansion, browserslist, follow-redirects, form-data, glob, lodash, minimatch, nanoid, next, picomatch, postcss, postcss-selector-parser, source-map-js, yaml and zod. Raw advisories and ranges are recorded in evidence/dependency-advisories.json. This is lockfile vulnerability matching, not proof of exploitability in a static export or a full installed-tree npm audit. Bun on this machine has no audit command.

Next 14 is outside the supported major-version table; official guidance recommends a current supported release. Upgrade rather than patching only cosmetic files. Re-audit the final resolved production and development tree. Static export avoids many runtime server paths, but dependencies and preview servers still require maintenance.

Official references checked:
- [Next.js support policy](https://nextjs.org/support-policy)
- [Next.js May 2026 security release](https://vercel.com/changelog/next-js-may-2026-security-release)
- [Next.js MDX guide](https://nextjs.org/docs/app/guides/mdx)
- [Zod schema parsing](https://zod.dev/basics)
